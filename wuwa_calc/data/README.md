# data/

Generated by `python tools/extract.py` from `old.xlsx`. Regenerating is idempotent.

This is the **Phase 1 / parity** shape: field names and semantics still match the
spreadsheet, so the ported engine can be validated against `TUNETEST` before the tag
system is redesigned (PLAN.md). Optional fields are omitted rather than written as
`null`/`0`, so `if (a.offtune)` is safe but `Object.keys` counts vary per record.

**Tag values are lowercased; names are not.** Google Sheets' `MATCH` is case-insensitive,
so the sheet had ~800 tag cells disagreeing on capitalisation (`atk`/`ATK`, `aero`/`Aero`,
`basic`/`Basic`) that worked anyway — a JS `===` port would silently drop those buffs.
Gear names stay case-sensitive: `CD ele ATK atk atk` and `CD ele atk atk atk` are
genuinely different Mainstats rows.

## config.json
```jsonc
{
  "constants": {
    "enemyLevel": 100, "resonatorLevel": 90, "defaultRes": 0.2,
    "dotConst": 3674,      // == levels[90].dot; kept only for parity
    "tuneConst": 10027,    // == levels[90].tuneRate * maxOfftune * 10000
    "maxOfftune": 39.2     // not in the sheet's Config; derived from the scratch sheets
  },
  "enums": {
    "scopes":   ["self","team","next","last","other"],
    "nodes":    [...5],  "scalings": [...5],  "elements": [...7],
    "types":    [...11], "specials": [...7],  "actionIds": [...24],
    "stats":    [...44],     // canonical spelling; FINDINGS.md sec 5 has the role split
    "categories": [...9]     // gear categories; case-preserved to match gear.category
  }
}
```
`specials` includes `midair`, which the extractor adds because 11 Luuk actions use it but
`Config!H` never declared it (FINDINGS ③). Prefer `levels.json` over `dotConst`/`tuneConst`
so level becomes a real input.

## levels.json — 90 records
Per-level dot/tune constants, from the `TUNEDOT` sheet. The **only** source for these.
```jsonc
{ "level": 90, "dot": 3674, "tuneRate": 0.025579218 }
```
Tune base damage = `totalOfftune * tuneRate`; dot base damage = `dot`.

## gear.json — 308 records
The registry of everything that can carry buffs — resonators, weapons, sequences, echo
sets, mainstat/substat lines, and abstract `Mode` rows (`Xuanling 2f1a`) that select a
playstyle. `name` is the join key into `stats.json`.
```jsonc
{ "name": "Thousandfold Deliverance", "category": "Weapon",
  "shorthand": "r1",          // optional
  "cost": 0.6666666667 }      // optional; budget number summed per build
```
Categories: `Weapon` 56, `Resonator` 42, `Mainslot` 42, `Mode` 36, `Sonata` 34,
`Mainstats` 35, `2pc` 26, `Sequence` 21, `Substats` 16.

## actions.json — 1051 records
```jsonc
{ "id": "Jingran: Lib1",        // `${source}: ${action}`, trailing ": " trimmed
  "source": "Jingran", "action": "Lib1",
  "multiplier": 4.968,          // motion value, as a fraction

  // resource deltas -- all optional, negative = spend. Display-only.
  "energy": -125, "concerto": 20, "offtune": 16.8, "forte1": 800, "forte2": 0, "dots": 0,

  // tags -- all optional, all lowercase
  "node": "liberation",         // NOT matched against (see below)
  "element": "fusion", "scaling": "atk", "type": "heavy",
  "special": "erosion", "buffId": "action1" }
```
`offtune` is already divided by 10000 (the sheet stored it pre-multiplied).

**The matched tag set is `element, scaling, type, special, buffId` — `node` is excluded**,
mirroring `Calculator!O`. So a `stats.json` entry can never match on a node today
(FINDINGS ②); `node` is currently display metadata.

`scaling` selects which stat the damage scales off: `atk`/`hp`/`def` read the
corresponding final stat, while `dot`/`tune` use the flat constants and bypass
amplification, damage bonus and crit entirely.

## stats.json — 1459 records
The buff database. One record = one stat modifier. **This is the core data.**
```jsonc
{ "name": "Jingran",       // a gear.json name, or "global"
  "scope": "self",         // self | team | next | last | other (config.enums.scopes)
  "value": 0.25,           // the coefficient
  "stat": "damageBonus",   // which stat it modifies
  "burst": false,          // true = applies only inside the on-field window
  "type": "heavy",         // optional tag filter; ABSENT = applies to every action
  "scaler1": "baseAtk",    // optional: multiply by this stat's current value
  "scaler2": "bonusAtk",   // optional: multiply by clamp(value, start, end) - start
  "start": 0, "end": 999,  // optional bounds for scaler2
  "notes": "final stat" }  // optional free text from the sheet
```
Contribution = `value × (scaler1 ? statValue(scaler1) : 1) × (scaler2 ? clamp(statValue(scaler2), start, end) − start : 1)`.

`start` is an **offset, not just a floor** — `start: 3, end: 12` means "count only stacks
above 3, cap at 12". The classic worked example, `flatAtk`, is two records:
`baseAtk × bonusAtk` plus `baseAtk × 1` = `baseAtk × (1 + bonusAtk)`.

Scope counts: self 1249, team 137, next 49, last 13, other 11. Scope resolution is
**cyclic** over the 3 slots — see FINDINGS §3 step 3.

## rotations.json — 69 records, 917 action slots
```jsonc
{ "name": "suisui",
  "actions": ["Suisui: Intro", "Suisui: FSkill", ..., "Suisui: Outro", ...],
  "burst": [true, true, ..., false] }  // optional, parallel to actions
```
`burst` is the on-field window: from the **last** action whose name contains `"Intro"` up
to (not including) the **first** `"Outro"` at or after it. Records with `stats.burst =
true` apply only where this is `true`. Verified against the sheet's cached `Rotations!K`
for all 69 rotations, and recomputed live in the editor when actions are edited or
reordered (`computeBurst` in `web/js/schema.js` matches the extractor).

These lists are **complete**: they include the 51 rows the old sheet excluded via its
sparse name column. Those were all 0% MV actions, so the exclusion was a speed
optimisation rather than a bug (FINDINGS ⑥) — adopting them leaves damage identical and
makes the resource totals whole.

## builds.json — 208 records
A resonator plus its 9 gear slots and a rotation.
```jsonc
{ "name": "jingran r1 cov cr/cd",
  "resonator": "Jingran", "weapon": "Thousandfold Deliverance",
  "mode": "...", "sequence": "...", "mainslot": "Myriad Snare",
  "sonata": "Crown of Valor 3pc", "twopc": "Lamp of Nether Road 2pc",
  "mainstats": "CR CD hp hp hp", "substats": "chem hp heavy",
  "rotation": "jingran" }
```
All slots optional (`twopc` is the sheet's `2pc`, renamed to be a valid identifier). Cost
is *not* stored — recompute it as the sum of the slots' `gear.cost`.

Known dangling references, reported on every extract and left in place deliberately:
`Jingran S1`/`Jingran S2` (sequences absent from Gear), mainstat `CD ele atk hp hp`, and
rotation `erover mdps` (2 builds). See FINDINGS ④.

## teams.json — 209 records
```jsonc
{ "name": "qx r1 denia r1 reel mornye r1",
  "enabled": false,                       // the sheet's calculate-me checkbox
  "slots": ["build a", "build b", null],  // always length 3
  "sheetDpr": { "slot1": 123456, "team": 456789 } }   // optional
```
`sheetDpr` is **not trustworthy as expected output.** `Teams!B/D/E` fall back to a
hand-typed number when the live sum is 0, and only **1 of 209 teams is enabled**, so
almost every value is stale. Use it as a rough diff signal only; `TUNETEST` is the real
ground truth (PLAN.md step 5).
